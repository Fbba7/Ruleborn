# Handoff: Ruleborn — mobile game screens, 3D world and characters

## Overview
Ruleborn is a portrait mobile strategy game. Each player keeps a small universe of floating islands ("realms") around a central island, the Heart. They weave **laws** (rules of physics, time, light and life) into realms, build and defend those realms, and raid other players' universes with a crew of creatures ("ruleborn") in short real-time heists.

This bundle contains:
- **28 interactive game screens** inside one phone frame (390 × 844 pt), with working navigation, a bottom nav bar, a 3D universe map, a 3D realm view and a playable heist.
- **43 character pages** (18 ruleborn kinds, 6 Sages, 3 Paradox-born, 3 Visitors, 3 Anomalies, 3 law creatures, 7 kinds of realm wildlife). Each page has a 3D hero view, an in-game animated view, a turnaround, expressions and forms.
- **An icon set of 31 groups** drawn as painted SVG objects.
- **The game design document (GDD v3.4)** and the latest screen review brief, which the screens follow.

The target engine is **Godot 4.7.2** (GDScript). The prototype is built in HTML, CSS and three.js r184.

## About the design files
The files in `prototype/` are **design references built in HTML**. They show the intended look, layout, copy, numbers and behaviour; they are not production code. The task is to **recreate them in Godot 4.7.2** using Godot's own patterns: Control nodes and Themes for the UI, and Node3D scenes for the islands, buildings and characters. Use the HTML as the specification, and read the source for exact values.

Where the design and the GDD disagree, **the GDD wins** (`docs/ruleborn-game-design-v34.html`). `prototype/ruleborn-data.js` is generated from the GDD and is the single data source for laws, realms, links, landing spots, crew and Sages. Port it to Godot `Resource` files or JSON rather than retyping values.

## Fidelity
**High fidelity.** Colours, type, spacing, copy, numbers and interactions are final. Recreate the UI pixel-accurately at 390 × 844 logical points and scale it to the device; landscape is not supported.

The 3D scenes are also high fidelity for composition, camera, palette, scale and motion. The meshes themselves are generated by code at runtime. Treat them as the art reference; they can either be exported (see Characters) or rebuilt in Blender.

## How to run the prototype
1. Serve `prototype/` over HTTP. ES modules and `fetch` don't work from `file://`. For example: `cd prototype && python3 -m http.server 8080`.
2. Open `http://localhost:8080/Ruleborn%20Screens%20v3.dc.html`.
3. An internet connection is needed. React and three.js load from unpkg, and fonts load from Google Fonts.
4. The left column is the screen index: tap any row to jump to that screen. **Characters** and **Icons** are tabs at the top of the index. A Tweaks panel exposes `heistOutcome` (Clean / Loud / Partial / Foiled), `leftHanded` and `ageBand` (18+ / 13–15).
5. Each screen's root element carries `data-screen-label="NN Name"`; search for it to find its markup and inline styles.

## Global layout (all screens)
- **Canvas:** 390 × 844 pt, portrait. Status bar 0–48 pt (time left, battery right, white 16 pt bold).
- **Screen header:** top 50 pt, height 44 pt, side insets 12–14 pt. It holds a 40 × 40 round back button on the left, the title (Lilita One 26 pt, `#FFF6DA` with a `0 2px 0 #1A0C14` text shadow, or Marcellus 26 pt on older screens) and an optional currency or action pill on the right.
- **Bottom nav bar:** 92 pt tall, pinned to the bottom, with five tabs: **Islands, Laws, Heist, Crew, Friends**. Heist sits in the centre and is raised. The bar uses a dark violet gradient (`#2E2466` → `#211A4C` → `#150F30`) with a 3 pt gold top rim (`#E9B65C` over `#6B4420`).
  - **Selected tab:** a raised violet plate with a gold rim, a soft glow behind the icon, the icon scaled up and the label shown.
  - **Unselected tab:** the icon and its label only.
  - Tabs have no dashed patterns or ray patterns; both were removed at the user's request.
- **Scroll areas:** they sit between the header (or tab bar) and 96 pt above the bottom, with hidden scrollbars and 14 pt bottom padding. Sideways scrolling of the page is not allowed; only explicit carousels scroll horizontally.
- **Tap targets:** the GDD (12.7) asks for at least 48 pt and never more than eight controls at once during a heist. See Open items: a full size pass is still outstanding.

### Typography
Three Google fonts. Bundle them as `.ttf` in Godot.
- **Lilita One** 400: numbers, buttons, names, card titles. Common sizes: 13, 15, 16, 17, 19, 20, 21, 24 and 26 pt, at line-height 1.
- **Marcellus** 400: serif screen titles on some screens, at 26 pt.
- **Manrope** 500–900: body and labels.
  - Body text: 700 at 12–12.5 pt, line-height 1.35–1.45.
  - Section labels: 900 at 9.5 pt, letter-spacing .14em, uppercase.
  - Small metadata: 800 at 10–11 pt.
- Text shadow on light-on-dark display text: `0 2px 0 #1A0C14`.

### Radius
- Chips and pills: 8–12 pt.
- Buttons: 11–17 pt.
- Cards: 14–20 pt.
- Bottom sheets: 26 pt on the top corners.
- Round buttons and portraits: 50%.

### Shadows
The style uses hard, offset, unblurred bottom shadows that make things look stacked, like a board game:
- Gold elements: `0 3–5px 0 #4A2A10`.
- Dark elements: `0 3–5px 0 #0A0618`.

A soft blurred shadow is added only on floating cards and sheets. Pressed state: translate down by 2–3 pt and drop the shadow by the same amount (`style-active` in the source).

### Spacing
The scale is 4 / 6 / 8 / 10 / 12 / 14 / 16 / 18 / 22 pt. Screen side insets are 12 pt, the gap between cards is 8–10 pt, and inner card padding is 10–16 pt.

## Interactions and behaviour (cross-screen)
- **Navigation:** every screen is reachable from the nav bar, the Universe map HUD, or a single linked action. The intended routes are listed in `SCREENS.md`. Back returns to the screen that opened it.
- **Screen transitions:** about 0.3 s. The old screen fades and scales slightly down (`scale(.985)`); the new one fades in.
- **Entering a realm from the map:** the camera dives toward the island with an ease-out over about 1.2 s, then the realm view's UI fades in. Moving between realms in the realm view uses a lateral camera slide, not a cut.
- **Toasts:** a short message pill near the bottom that auto-hides after about 2 s, used for confirmations ("Invite code copied").
- **Sound and haptics:** `RBSfx.play(name)` with the names `tap`, `open`, `collect`, `place`, `error`. Map them to Godot `AudioStreamPlayer` sounds plus `Input.vibrate_handheld`.
- **Loading:** 3D content shows a spinner until it is ready. Characters stream in one at a time so the UI never freezes; keep this staging in Godot by instancing scenes across frames.
- **Age bands:** `ageBand` changes behaviour in several places:
  - Shop spending limits.
  - Challenge links go only to in-game friends for players aged 13–15.
  - Gifting needs a parent's approval for minors.
  - Play-time reminders are locked on for players aged 13–15.
  - The age check on screen 20 sends each band down its own first-session path (GDD 20.7).

## State
The prototype keeps all state in two component classes; a Godot version would use a few autoload singletons. Key state:
- **Player:** resources (Starlight, Aether, Essence, Pages, Insight, Starglass), Keeper level, Renown, league and age band.
- **Realms:** for each realm, its woven laws per slot, buildings with grid position and level, terrain tiles, guard posts and wards, and stability. Strain bands are Quiet, Steady, Humming and Strained.
- **Crew:** for each creature, its state (idle, working, guarding, on a heist, resting, asleep), rest timer, level and XP, form and traits.
- **Heist session:** crew positions, gait per crew member (crouch, walk or run), stamina, HP, guard suspicion (0–1,000), alarm meter, loot, clock, ability charges and outcome.
- **Collections:** found laws and mastery, resonances (12), forms (54), season tier and claimed rewards, shop purchases and friends.

Server data the prototype fakes: matchmaking targets (Observatory), scout intel, friends' presence and feed, the defence log and season time remaining.

## 3D (`prototype/realm-diorama.js`)
One custom element, `<realm-diorama>`, renders every 3D view. Its attributes:
- `mode`: one of `universe`, `plan`, `realm`, `heist`, `scout`.
- `realm`: which island to show.
- Plus `route`, `tab`, `intel` and `defence`.

It reports taps and state back to the UI through `CustomEvent('rb-diorama')`. Port it as one Godot scene per mode that shares an island generator. What to keep from the reference:
- **Islands:** each one is a floating rock with a grass cap, terrain tiles, buildings that sit on a grid (with different footprint sizes) and ambient wildlife. Ground continues below the island like an iceberg, so it never looks like a flat plate.
- **Camera:** a high three-quarter angle. Players pinch to zoom and twist to rotate; there are no zoom buttons.
- **Links between islands:** three kinds connect the realms to the Heart and to each other: stone bridges, rope bridges and chutes (`ULINKS`).
- **Ships:** only raid skiffs fly, and only along links or to a landing edge, never at random.
- **Universe background:** animated and alive, with stars, drifting planets and motes. It has no compass, no jellyfish and no kites; the user asked for these to be removed.

## Characters
See **`CHARACTERS.md`**. Each character is a JavaScript module that builds a three.js mesh in code and exports:
- `build(opts)`: returns the source geometry. Skinned meshes are built with `creature-kit.js`.
- `makeRig(src)`: returns the rig, with bones and an `apply(clip, t)` call.
- `CLIPS`: procedural animation clips. Tidewalker's are idle, ability, wade, nap, work, calm, focus, startled and caught.
- `EXPR`: expressions.

Four heavy characters (Archivist, Skyskipper, Mossbear, Featherkin) also ship pre-baked meshes as `.bin` files.

**Getting them into Godot:** `GLTFExporter` is already in each rig page's import map but isn't wired up yet. The recommended path is:
1. Build each character with `build()` + `makeRig()`.
2. Sample every clip at 30 fps into `THREE.AnimationClip` tracks.
3. Export a `.glb` per character.
4. Import it into Godot as a `.glb` scene with its `AnimationPlayer`.

## Icons
`prototype/ruleborn-icons.js` defines 31 groups:

hud, currencies, buildings, wards, realms, links, stabilitybands, lawnotes, harmony, laws, paradoxes, lawranksandtiers, crewroles, characterstates, traits, sagepowers, heistcontrols, heiststatus, heistoutcomes, terrain, leagues, season, constellation, social, alerts, realmactions, planningactions, generalui, screens, shopcosmetics, settingsandwellbeing

Each icon is a painted SVG object with a dark outline and a highlight, drawn on a 24-unit grid. `RBI(group, name)` returns it as a data URL. The Icons tab of the index shows them all. To use them in Godot:
- Export each icon as an SVG file: run `RBI` in a browser and save the decoded data URLs.
- Or rasterise each one at 128 and 256 px.
- Then import them into Godot as textures.
